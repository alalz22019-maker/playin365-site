# PlayIn365 — Golden Match Day

## القرار التنفيذي

`matchDay` هو ثاني رحلة تشغيلية كاملة فوق الركائز الثلاث، بعد `trainingDay`:

- **الأفراد:** اللاعب والمدرب والإداري وصاحب صلاحية النتيجة.
- **الجهات:** الأكاديمية والفريق والمنافس والجهة المنظمة.
- **الأحداث:** المباراة كسجل واحد يربط الموعد والتوفر والجاهزية والتشكيلة والأحداث والنتيجة والأدلة.

لا تُحذف أي صفحة مباراة قديمة. تبقى `acadMatches` و`orgMatch` و`tactics` و`boards` والتقارير متاحة، بينما يضيف `matchDay` نقطة التشغيل المشتركة اليومية.

## الرحلة

```text
الأكاديمية تنشئ المباراة وتحدد الفريق والمنافس والمدرب والملعب
→ المدرب يبني القائمة والتشكيلة وينشرها
→ اللاعب يؤكد توفره ويحدث جاهزيته
→ المدرب يرى المؤشر دون الملاحظة الخاصة
→ تُفتح المباراة المباشرة
→ تُسجل الأهداف والصناعات والتبديلات والبطاقات
→ يغلق المدرب سجل فريقه
→ تعتمد الجهة المخولة النتيجة الرسمية
→ تتحدث المشاركات والدقائق والمؤشرات وهويات اللاعب والفريق والمباراة
```

## الحوكمة

- الطاقم الفني يستطيع إدارة قائمة فريقه وأحداثه.
- المدرب يستطيع إغلاق سجل فريقه، لكنه لا يتجاوز سلطة اعتماد النتيجة.
- الجهة المخولة تعتمد النتيجة وتُنشئ Revision موثقًا.
- اللاعب يرى بياناته ودوره ونتيجته فقط، ولا يرى جاهزية زملائه.
- الملاحظة الخاصة للجاهزية لا تظهر للمدرب أو الأكاديمية.

## تجربة الواجهة

PlayIn Live Match Canvas يتكون من:

- Match Scene وScore Stage.
- Formation Pitch.
- Readiness Field.
- Live Roster.
- Match Event Timeline.
- Context Sheets للإنشاء والتشكيلة والجاهزية والأحداث والنتيجة والإغلاق.

## معايير الإغلاق

- 97/97 مسارًا عبر الأكاديمية والمدرب واللاعب.
- لا صفحات أو خدمات مفقودة.
- رحلة بيانات كاملة من الإنشاء إلى تحديث هوية اللاعب.
- تطابق الشكل الهندسي الرسمي `TL / BL / BR`.
- لا تمدد أفقي على 390×844.
- أهداف اللمس الأساسية 44px فأعلى.
- فحص Preview ثم Production قبل ختم `production_verified`.
